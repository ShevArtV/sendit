2.10.0-pl
==============
- Добавил вход и регистрацию по одноразовому коду (только MODX 2): сниппет siSendCode, валидатор
  siCheckCode, хук siCodeIdentification, пресеты code_send, code_send_register, code_auth,
  code_register, пример формы siExampleCodeAuthForm. Код хранится HMAC-хэшем под ключом получателя,
  а не сессии; лимиты codeTtl, codeResendDelay, codeAttempts, codeHourlyLimit, codeLength задаются
  в пресете. Телефон ищется по цифрам, без учёта маски в профиле.
- Доставку кода пакет не реализует: проект пишет класс с интерфейсом siCodeSender (SMS, Telegram,
  почта) и подключает его настройками si_code_sender, si_code_sender_path или параметрами пресета
  codeSender, codeSenderPath.
- Добавил события siOnBeforeSendCode (подменить код или запретить отправку) и siOnCodeLogin.
- Добавил сохранённую корзину покупателя (таблица si_user_carts, действие savecart): корзина
  сохраняется на событиях корзины miniShop2 и возвращается при входе с другого устройства;
  совпавшая позиция получает большее количество, а не сумму. Работает при ms2_tmp_storage=session.
- Добавил заявку на возврат из кабинета (действие return, пресет order_return): выбор позиций
  и количества, причина, комментарий. Настройки si_cabinet_return_statuses и
  si_cabinet_return_days. Что делать с заявкой, решает проект на siOnUserCabinetAction
  (method requestReturn).
- Параметр пресета reloadPage работает для любых пресетов, а не только кабинета.
- Чанки кабинета и примеры форм свёрстаны в стиле остальных примеров пакета.

2.8.4-pl
==============
- Закрыл запись файла с произвольным именем и путём через публичный экшен uploadChunk:
  имя из заголовка X-CONTENT-NAME больше не подставляется в путь. Приём чанка разрешён
  только для файла, который прошёл serverside-валидацию (validate_files) в этой же сессии,
  с теми же расширением, размером и пресетом; все пути проверяются на принадлежность
  каталогу загрузок сессии до создания каталога и записи.
- Закрыл удаление произвольного файла через removeFile: путь проверялся вхождением
  session_id в строку, поэтому uploaded_files/{sid}/../../../core/config/config.inc.php
  проходил проверку. Теперь путь канонизируется и обязан остаться внутри каталога
  загрузок сессии. Флаг forceRemove для внутренних вызовов сохранён.
- Закрыл path traversal в attachFiles(): список файлов из POST подставлялся в путь
  без проверки.
- Добавил серверную нормализацию имён файлов (транслитерация без ext-intl, kebab-case,
  нижний регистр расширения, лимит длины) и обезвреживание исполняемых расширений:
  shell.php -> shell-php, shell.php.jpg -> shell-php.jpg.
- Добавил событие siOnSanitizeFileName: проект может задать свои правила именования
  вплоть до полного переименования файла и раскладки по подкаталогам. Параметры: name
  (оригинал), sanitized (имя по правилам пакета), extension, directory, context,
  formName, presetName, SendIt; ответ — returnedValues['name'], пустой ответ означает
  "дефолт устраивает". Имя, вернувшееся из плагина, в любом случае проходит
  security-постфильтр пакета.
- validate_files возвращает карту data.names (исходное имя -> имя на сервере), клиентский
  загрузчик работает по ней. На сервер теперь уходит исходное имя файла, чтобы плагин
  проекта получал оригинал, а не результат клиентской транслитерации.
- Удаление файла, загрузка которого не завершилась, убирает каталог его чанков, а не
  каталог сессии целиком.
